# Dream Street

English | [简体中文](README.zh-Hans.md)

An endless daylight street, and the self who dances in its windows.

## Background

A man in an old long coat walks down a sunlit street and never stops. He only walks; his reflection in the shop windows dances, and changes clothes whenever a window's display touches it.

The street is alive around him. Along the way, people are browsing windows, waiting at a crossroad, chatting, walking and cycling. As he comes near, they turn, fall into step and try a few of his moves. At the next crossroad they wave and go their own ways.

Dream Street recreates a dream as a small browser experience. Everything you see and hear is generated by code: the street, the people, the dance and an original score for a small rock band. The walker steps on every beat, at 128 BPM.

## Play

- Online: <https://gamebygame.github.io/dream-street/>. While the domain is active, <https://dream-street.jovipro.com/> serves the same build as an alias.
- Locally: install, start the dev server, open `http://127.0.0.1:5173/` and press start (开始前行).

```sh
npm ci
npm run dev
```

Hiding the page pauses it; press continue (继续) when you come back. Mute only changes the volume. The development and preview servers listen on `127.0.0.1` only.

## Repository boundary

- **Tracked:** the application source (`src/`), tests (`tests/`), review and capture scripts (`scripts/`), documentation (`docs/`), the build, CI and Pages configuration, and the Cloudflare Worker that serves the jovipro address (`deploy/`).
- **Not tracked:** `artifacts/` (review frames, music renders, recordings and reports), `dist/`, `node_modules/` and caches. These are evidence and build output, and they can be regenerated.
- **Never tracked:** credentials, personal data, absolute local paths, and third-party media without a licence to redistribute it.

## Truth boundary

- The code is the source of truth for behaviour. The authored timeline in `src/content/plan.js`, the choreography in `src/character/pose.js`, the crowd in `src/content/crowd.js` and the score in `src/audio/score.js` are creative decisions; change them only with the maintainer.
- [docs/INTENT.md](docs/INTENT.md) is the intent ledger: what each request meant, how it maps to the code, and what remains open. Read it before changing motion or music.
- [docs/VERIFICATION.md](docs/VERIFICATION.md) records only the checks that were actually run in each round.
- [docs/ASSETS.md](docs/ASSETS.md) records every reference, dependency and licence.

The ledger and the verification record are working records kept in Chinese, the language the decisions were made in. Everything else is in English.

Tests passing does not mean the dream works. Whether the picture, the motion and the music feel right is decided by watching and listening.

## Verify

Node 22.12 or later (development uses Node 24.20.0 and npm 11.19.0). Dependencies are pinned in `package-lock.json`.

```sh
npm run format:check
npm test               # unit tests
npm run test:browser   # browser tests in the local Chrome; needs a local port
npm run build
npm run preview
```

Review tools, with the dev server running:

- **Debug view:** `?debug=1` adds beat jumps, contact lines, per-stem toggles and recording.
- **Close-ups:** `?debug=1&inspect=walker|dancer|crowd|cyclist&index=N&zoom=3.6` keeps the production camera angle and projection, zoomed in on one character, so arms and elbows can be judged.
- **Frames at the same beats:** `node scripts/review-frames.mjs --label <name>` saves close-ups and full frames to `artifacts/review/<name>/` for side-by-side comparison between rounds.
- **Music renders:** `node scripts/render-music.mjs --label <name>` renders each chapter, the four-hit and the loop seam to WAV in `artifacts/music/<name>/`. It records peak, RMS, crest factor and low-frequency share, and for each four-hit accent its onset error and loudness percentile.
- **Balance:** `node scripts/balance-music.mjs` solos each stem over each chapter.
- **Recording and soak:** `npm run capture` records one cycle with the score's audio while soaking. The default soak is 600 s; set `DREAM_STREET_SOAK_SECONDS` to change it. Reports go to `artifacts/capture/`. `DREAM_STREET_MUSIC=silent` gives a silent run for motion checks.

## The music

The score shares one beat timeline with the street, the wardrobe and the dance; its four chapters are the street's four windows.

| Beats | Chapter | Music |
| --- | --- | --- |
| 0–80 | Sparks (电光) | Driving G-minor rock: a power-chord riff doubled by guitar and bass. Beats 50, 52, 54 and 56 are the four-hit, stop-time hits of the whole band; beats 60–72 are a piano interlude past the offices. |
| 80–144 | Together (同行) | The gathering crowd's own stamp-stamp-clap over a funk-rock bass line, growing with the people who have joined; once everyone is in step, the band lands with twin harmony guitars. |
| 144–208 | Flowers (花间) | A piano ballad in E-flat with a soft heartbeat and a violin-like guitar, and no driving drums. |
| 208–256 | Parade (游乐) | Piano-driven glam rock in B-flat with twin harmony guitars. |

The band is played clean, in the manner of 1970s rock: a dry kit with modelled bronze cymbals, crunchy rather than high-gain guitars, piano, and only a few parts at once, with no synthesisers or pads. Every beat carries an audible pulse, and every chapter entrance is led in by a drum fill. The mix chain's own latency is measured at start-up (about 6 ms in Chrome), and notes are scheduled that much earlier so sound lands on the beat that is shown.

The music panel's comparison switch plays the Sea Power recording that served as a benchmark for power, through YouTube's official player. It mutes the score but not its clock: the picture keeps following the score, and the two are not aligned. The comparison is never recorded.

## Layout

| Path | Contents |
| --- | --- |
| `src/content/` | The 256-beat street, products and wardrobe state, performance chapters, and the street life and paths of passers-by and cyclists |
| `src/character/` | The body template, skeletons and IK (elbows bend anatomically), gait, the dance phrases and cloth light |
| `src/audio/` | The single clock (`transport.js`), the score (`score.js`), instruments (`instruments.js`), guitar chords and cymbals rendered at load time (`tones.js`), the mixer (`mixer.js`), offline rendering (`render.js`), and the comparison-only reference player (`reference.js`) |
| `src/world/` | Three recycled street segments, 36 instanced passers-by and two bicycles |
| `src/render/` | The fixed orthographic camera, the shared reflection texture, glass tint and clipping, and the debug close-up camera |
| `docs/` | The intent ledger, the verification record, and assets and licences |
| `deploy/` | The Cloudflare Worker that serves the build at dream-street.jovipro.com, and how it is set up |

## Deployment and rollback

Every push to `main` builds the site and publishes it to GitHub Pages at <https://gamebygame.github.io/dream-street/> (`.github/workflows/pages.yml`). <https://dream-street.jovipro.com/> serves the same files through a small Cloudflare Worker; [deploy/README.md](deploy/README.md) explains why and how it is set up. Pull requests run formatting, unit tests and a build (`.github/workflows/ci.yml`). To roll back, revert the commit on `main`; the workflow republishes the earlier state, and both addresses follow. You can also re-run the Pages workflow on an earlier commit.

## Releases

Versions follow [Semantic Versioning](https://semver.org/), and [CHANGELOG.md](CHANGELOG.md) records each one. Pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`. It builds that tag and publishes its GitHub release with:

- the built site as `dream-street-X.Y.Z-site.zip` and `.tar.gz`, each with the licence (any static file server can serve it, at any path);
- `SHA256SUMS` for both archives;
- signed build provenance, checked with `gh attestation verify <archive> -R gamebygame/dream-street`.
