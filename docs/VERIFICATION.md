## 实时录制与运行采样

录制和采样由 `npm run capture` 生成，完整机器记录位于 `artifacts/g1/capture-report.json`。使用 1440 × 900、DPR 1，实际渲染主场景和倒影两遍，绘制调用统计在两遍之前统一清零。帧间隔以 `performance.now()` 测量，包含浏览器调度、录制和两次渲染之间的间隔；不是单独 GPU 耗时，也不代表高 DPR 或其他设备的表现。

脚本连续运行约 125 秒，覆盖三个完整 80 拍街道循环后进入第四轮；每 20 秒采样对象、纹理、声音和调度器。视频的前 40.5 秒为原镜头、正常速度、应用 Canvas 加应用音频流；不是离线逐帧动画，也没有外部配音。录制音频支路根据输出时间映射补偿延迟，但未使用外部回环设备测量扬声器和显示器之间的绝对同步误差。

最终数值在 `capture-report.json` 中以 `final.visual`、`final.audio` 和 `samples` 为准。首次经过全部街段会有 GPU 几何预热增长，后续同相位采样应保持稳定；没有用强制归零时间或每轮重建场景来通过稳定性检查。

## 视频和构建

视频提供 WebM 原始录制，以及 H.264 / AAC 的 MP4 便于播放。关键帧在 `frame-50.png`、`frame-52.png`、`frame-54.png`、`frame-56.png`；另有旧装、接触、间断、回归及 1600 × 900 构图图像。

音频存在性和峰值由 FFmpeg 测量；它只能证明录到了声音和电平范围，不能证明编曲已经好听。全速观看与实际试听仍由体验评审决定。

最终 MP4 长 40.500 秒，1440 × 900、60 fps，H.264 视频加 48 kHz 双声道 AAC，10,638,641 bytes。原始录音平均电平 −20.3 dBFS、峰值 −4.8 dBFS；媒体和电平记录在 `media-info.json`、`audio-analysis.txt`。MP4 转码保留原始实时录制的声音和画面节奏。

`npm run build` 通过。Vite 提示主 JavaScript chunk 超过 500 kB，主要含 Three.js；保留这条提示，没有提高警告阈值掩盖它。构建日志在 `artifacts/g1/build-results.txt`。网络访问只需安装依赖，应用运行本身没有远程素材请求、遥测或外部 API。

## G1 评审仍需决定

- 玻璃染色、透底与表面反光是否足以让倒影被认作“映出的形象”，同时仍看得清姿势。
- 真人与倒影是否自然被认作同一个人，四套服装轮廓和脚下重量是否成立。
- 能否在完整镜头里看到商品先出现、接触后换装，连续四次变化与音乐重音是否清楚。
- 原创七声部音乐是否形成愿意继续听的乐句；旧装恢复以后，舞蹈的力量是否还在。

这些问题未通过之前继续修改核心片段，不扩展 G2。包含人群的 10 分钟稳定性测试属于 G2，本轮未执行。
